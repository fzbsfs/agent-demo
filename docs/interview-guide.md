# Agent Demo 面试讲解稿

这份文档教你"怎么把一个 Demo 讲成一个会加分的故事"。
核心心法：**不要背稿，要讲原理**。面试官追问任何一个点，
你都能回答"为什么这么做"。

## 一、30 秒开场白（自我介绍用）

> 我做了一个 Agent 小项目：一个会调用工具、会检索本地知识库、
> 有跨轮记忆的多轮对话助手。核心是一个 Agent 循环：
> 大模型负责思考，决定要不要调用工具；工具负责真正干活；
> 结果再传回大模型，直到给出最终回答。我用 DeepSeek 的
> Function Calling 能力实现工具调度，用一段词频检索实现了
> 最简版 RAG，并接了一个 Streamlit 界面方便演示。

说完直接打开浏览器演示，比背更多八股有用一百倍。

## 二、现场演示话术（照着演）

1. 输入「帮我算 (8+2)/5」→ 点出：大模型决定调用计算器工具
2. 输入「现在几点」→ 点出：这也是工具，说明模型知道哪些事它自己干不了
3. 输入「什么是 RAG」→ 点出：触发知识库检索，讲"这就是 RAG"
4. 输入「记一下明天交作业」再问「待办清单」→ 点出：跨轮记忆 + 有状态工具

每步只讲一句话解释"刚才发生了什么"，不要冷场，也不要滔滔不绝。

## 三、按文件讲解（面试官深挖时）

### agent.py —— 最关键，多讲

核心是那个 `while True` 循环：
发消息 -> 大模型回答 -> 如果它要调工具就执行并把结果塞回历史 -> 继续问 -> 直到它直接回答。
另外加了**错误处理**：工具执行包在 try/except 里，出错把错误信息记回历史，
让大模型看到后换策略；还有最多 5 轮的调用上限，防止死循环。

一句话概括：**思考 -> 行动 -> 观察 -> 再思考**，这就是 Agent 的定义。

### tools.py —— 讲工具怎么被描述

`TOOL_SCHEMAS` 用 JSON Schema 描述"我有什么工具"，大模型据此决定调哪个。
`execute_tool` 是真正执行的地方。

### rag.py —— 讲 RAG 原理

问题 -> 向量 -> 和每段文档比相似度 -> 取最像的几段 -> 交给大模型。
我这个教学版用词频向量，生产会用 embedding 模型 + 向量库（如 ChromaDB）。

### app.py —— 一句带过

Streamlit 只是壳，方便演示和面试现场展示。

## 四、高频追问 TOP 10

### 1. 什么是 Function Calling？

让大模型在回答里输出"我要调用某个工具"的结构化指令（工具名 + 参数）。
程序检测到这个指令，执行对应函数，把结果以 tool 消息传回去。
重点：**不是大模型真的去执行，是它"说"想调，程序来调**。

### 2. 为什么用 Function Calling，不让模型直接输出 JSON？

Function Calling 是原生协议，输出结构稳定、带 tool_call_id 便于对应，
不用自己解析文本里的 JSON，减少格式错误和幻觉。

### 3. RAG 为什么不能把文档全塞进提示词？

上下文窗口有限，塞不下长文档；内容越多，注意力越分散，回答越差、越慢、越贵。
RAG 只把"相关片段"塞进去，成本低、效果好、还能随时更新知识。

### 4. 上下文窗口超了怎么办？

三个思路：截断最早的历史、把历史做摘要压缩、把内容移到向量库按需检索。
追问"你 Demo 里怎么做"→ 答：单轮历史不长，没处理；生产会做摘要 + 检索。

### 5. 大模型为什么会幻觉？怎么缓解？

模型是概率生成，不知道的会"编"。缓解：RAG 给事实依据、要求引用来源、
让模型说"不知道"、用工具替代记忆（查库而不是背）。

### 6. 你了解 LangGraph / CrewAI 吗？

它们是把"循环"做成可视化编排的框架：节点（Node）+ 边（Edge）+ 状态。
我的 Demo 手写循环是为了讲清原理；生产会用框架管理复杂流程、并行、重试。

### 7. MCP 是什么？

模型上下文协议，统一"大模型怎么连外部工具/数据源"的标准接口。
类比：LSP 统一了编辑器的语言支持，MCP 统一了 AI 的工具接入。

### 8. 你的 Demo 有什么缺点？怎么上生产？

诚实回答，这是加分项：
- eval 算表达式不安全，生产用表达式库或沙箱
- 词频检索不如 embedding，生产用向量库
- 历史无上限，生产要截断/摘要
- 没做鉴权和限流，生产要加
- 工具执行失败已做捕获并回传给模型换策略，调用轮数有上限；生产会加更细的重试和降级

### 9. 为什么用 DeepSeek？

中文效果好、便宜、API 兼容 OpenAI 协议，换 base_url 就能换厂商，
说明你懂"模型可替换"这一层抽象。

### 10. 现场写代码考什么？

常见：翻转字符串/数组、两数之和、最长公共前缀、简单排序、判断回文、
模拟一个简单函数。练熟这些就够撑住初级岗的现场题。

## 五、怎么证明这是你写的

面试官常问"框架帮你写了吧"。应对：主动挑一个细节讲实现，
比如"RAG 那段词频向量和余弦相似度是我手写的，因为我想先搞懂原理"。
能讲出取舍（为什么先手写、生产换什么），比说"全是我写的"可信得多。
